# v0.2 — 절차 생성 + 구역 체크포인트 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 한 판을 시드로 만든 4개 구역(첫 구역=튜토리얼)으로 구성하고, 구역 문을 지나면 다음 구역으로 넘어가며, 죽으면 그 구역만 새로 뽑아 입구에서 재시작하고, 새로고침하면 체크포인트에서 이어하게 만든다.

**Architecture:** 규칙은 계속 DOM·Phaser를 모르는 순수 모듈(`src/logic/`)에 둔다: 시드 난수기 → 구역 레이아웃 → 배치·검증·폴백(`buildZone`) → 판 상태(`Run`). `src/save.js`만 `localStorage`를 만지고 저장소를 인자로 받아 node에서 테스트한다. `PlayScene`은 `Run`에서 구역을 만들어 그리고, 레거시 `rows` 모드(v0.1 스모크용 `OPEN_ROOM`)는 그대로 유지한다.

**Tech Stack:** v0.1과 동일 (Phaser 3.90.0 vendored, ES modules, `node --test`, Playwright 스모크). 새 의존성 없음.

**Spec:** `docs/spec.md` (§4 구조·저장, §7 173 활성화, §8 무전, §10 맵 생성, §14 저장, §16 가정 11~13), `docs/roadmap.md` v0.2 섹션, `docs/decisions.md` D41~D49

## Global Constraints

- Phaser **3.90.0 (MIT)** `vendor/phaser.min.js`, 빌드 도구 없음, 모든 경로 상대 경로. 해상도 **480×270**, 타일 **16×16**, 렌더러 `Phaser.CANVAS`.
- 한 판 = **4구역**(`ZONE_COUNT=4`), 구역마다 별도 맵, 방 **3~4개**(튜토리얼은 **3개**), 통로 폭 **2타일 이상**, 방마다 **2×2 기둥 0~2개** (D41, D47).
- 구역 시드 = 판 시드 + 구역 번호 + 시도 횟수 (D42). `?seed=<숫자>`로 판 시드 지정.
- 재생성 상한 **50회**, 넘으면 고정 맵 폴백 (D46). 173은 입구에서 경로 **15타일** 이상·입구에서 시선 차단, 카드키와 겹치지 않게.
- 카드키는 **2~3번째 구역 중 한 곳**(구역 인덱스 1 또는 2)에 하나, 출구는 마지막 구역 끝. 첫 구역에는 카드키 없음.
- 173 활성화 (D45): 튜토리얼 구역은 **첫 목격까지 휴면**(이후 영구 활성), 이후 구역은 경로 거리 **14타일** 이내일 때만 추격. 휴면 중인 173은 안 움직이고 즉사도 아니다.
- 최단 경로 합계(시작→카드키→출구) 한 판 **450타일 이상**: 구역별 최소 `[90, 120, 120, 120]` (합 450). 구역 크기는 처음 **60×36**, 이 값으로 검증이 안 되면 최대 **64×40**까지 키운다.
- 저장: `localStorage` 키 **`gaze.run.v1`**, 내용 = 판 시드, 구역 번호, 시도 횟수, 카드키 보유, 들은 무전 줄. 새로고침하면 자동 이어하기, **R키 새 판**, 디버그(`?debug=1`)에서 **M키**로 안개 끄기+시드·구역·시도 표시 (D43, D44).
- 들은 무전 줄은 판 안에서 반복하지 않음, 재시작 포함 (D48).
- **v0.2에 없는 것**: 096, 문 닫기·잠금, 거짓 무전·신뢰도·엔딩, 스프라이트·합성음, 로커, 타이틀·크레딧.
- v0.1의 단위 테스트와 스모크 체크는 계속 통과해야 한다. 이 계획이 모양을 바꾸는 기존 테스트(`create173` 상태, `parseMap` K 필수)는 해당 태스크에서 고친다.
- 결정이 바뀌면 코드만 고치지 말고 `docs/spec.md`·`docs/roadmap.md`·`docs/decisions.md`도 고친다. 정해지지 않은 수치를 정하면 `Ruling:`으로 원장에 남기고 Task 12에서 spec §16에 반영한다.

## Review Focus

spec이 암시하지만 개별 테스트 밖에 있기 쉬운 상황 (각 줄의 테스트는 소유 태스크에 있음):

1. **저장 데이터가 깨졌거나 손으로 고쳐졌거나 버전이 다름** → 크래시 없이 새 판으로 시작. (Task 5, 6)
2. **`localStorage`를 못 씀** (접근 시 예외, 가득 참, 시크릿 모드) → 저장 없이도 끝까지 플레이 가능, 예외 없음. (Task 6, 11)
3. **R키를 실수로 한 번 누름** → 10분치 진행이 지워지면 안 됨. 3초 안에 한 번 더 눌러야 새 판. (Task 11)
4. **`?seed=`에 이상한 값** (빈 값, `abc`, `-5`, `1e9`, `12.5`, 2³² 이상) → 무시하고 저장된 판 이어하기 또는 무작위 시드, 예외 없음. (Task 5, 6, 11)
5. **같은 프레임에 173 접촉 + 구역 문 진입, 전환 중 입력** → 결과는 정확히 하나(접촉이 이김). 문 위에 머물러도 구역은 한 칸만 넘어감. 전환 중 Space·E는 무시. (Task 10)
